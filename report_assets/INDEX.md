# Report pack index

Everything here is generated by `python -m report.build_report` from the experiment outputs in `data/`.

## Figures (`figures/`, each as .png 300 dpi and .pdf vector)

| id | what it shows | suggested slide |
|---|---|---|
| `F01_architecture` | System architecture: hospitals, an untrusted server and the contract on a BFT chain; green marks zero-knowledge and on-chain verification. | architecture slide |
| `F02_privacy_vs_accuracy` | Privacy-utility trade-off. Left: test accuracy against the privacy budget epsilon for local DP (every hospital adds full noise) and our distributed DP under secure aggregation (noise split across hospitals); dashed line is FedAvg without privacy. Right: with epsilon fixed at 8, fewer communication rounds are better under DP. Mean +/- 1 s.d. over 8 seeds; four real hospital silos. | slide 17 |
| `F03_membership_inference` | Membership inference on 50 planted canary records against an over-fitted model. Attacker AUC falls from 0.66 without DP to chance (0.5) for epsilon <= 16; bars annotate the accuracy cost. Mean +/- s.d. over 5 seeds. | slide 18 |
| `F04_mia_roc_curves` | ROC curves of the loss-threshold membership-inference attack on planted canary records (log-log, the low-false-positive regime that matters for privacy). Without DP the curve lies above the diagonal; at epsilon <= 16 it collapses onto it. Mean over 6 seeds. | slide 18 (alt.) |
| `F05_server_view_leakage` | Cosine similarity between what the server receives from a hospital and that hospital's true update. Without secure aggregation the server reads every update (1.0); with it the similarity is zero for 4, 8 and 16 hospitals. 8 seeds. | slide 19 |
| `F06_attacks_undefended_vs_defended` | Seven attacks against the undefended system (DP + secure aggregation) and the full system. Labels show whether the full system detected the attack; label-flipping inside the norm bound is the stated limit. 20 seeds. | slides 20-21 |
| `F07_fixing_late_detection` | Fixing late detection. Random audits alone leave large variance (a late catch leaves a damaged model); the validation gate and the zero-knowledge norm proofs restore accuracy for persistent and sleeper poisoners. 16 seeds (ZK: 8). | slide 22 (new) |
| `F08_accuracy_vs_exposure` | Security against privacy exposure for each defence policy. ZK norm proofs reach the best accuracy with zero exposure of any hospital's data; the validation gate buys accuracy by opening honest hospitals in a third to a half of the rounds. Up and to the left is better. | new slide |
| `F09_vs_robust_aggregation` | Comparison with robust aggregation. Krum, median and trimmed mean resist the same attacks but require the server to see every individual update; ours hides all updates from the server at a small accuracy cost. 16 seeds. | new slide |
| `F10_ablation_layers` | Ablation: what each layer buys. Rows add one component at a time (FedAvg -> + DP -> + secure aggregation -> + ledger (commit, audit, verify) -> + validation gate -> + blame phase); columns are scenarios. Left: final accuracy. Right: whether the attack was detected. The gate rows train on 8% less data (held out as the public validation set), which costs about 0.02 on the honest run. 8 seeds, 8 hospitals. | new slide |
| `F11_convergence_curves` | Test accuracy per round (mean +/- s.d., 10 seeds, 8 hospitals, epsilon = 8 over 15 rounds). Our system tracks FedAvg closely and clearly beats local DP; under a sign-flip poisoner the undefended model is destroyed while the defended one recovers after the attacker is banned. | slide 17/21 (alt.) |
| `F12_per_hospital_accuracy` | Accuracy on each hospital's own held-out patients. The four real silos differ in size and case mix, so DP noise does not cost every hospital equally; 10 seeds, 4 hospitals, epsilon = 8. | backup slide |
| `F13_audit_rate_tradeoff` | Audit-rate trade-off. Left: the seeded-noise audit catches a hospital that skips its DP noise (statistical audit never does at 14 parameters). Middle: accuracy with a poisoner present against audit rate. Right: the price, the share of rounds in which an honest hospital is opened. | slide 22 |
| `F14_epsilon_over_rounds` | Privacy budget consumed per round as recorded by the contract, with 16 hospitals and 0/20/40% dropout (5 seeds). Dropped hospitals take their noise share with them, so the effective noise falls and epsilon grows faster than planned. | slide 24 (alt.) |
| `F15_dropout_tolerance` | Dropout tolerance. Left: rounds completed against the share of hospitals that disconnect. Right: epsilon actually spent; the contract charges the real cost, which rises with dropout because dropped hospitals take their noise share with them. | slide 24 |
| `F16_overhead_vs_clients` | Overhead of each layer against the number of hospitals: communication per hospital per round, compute per round, and measured gas on the real chain. | slide 23 |
| `F17_zk_proof_cost` | Cost of the zero-knowledge norm proof against model size: linear in the number of parameters (0.3 s at 14 parameters, 2.9 s at 256), so practical only for small models. | new slide |
| `F18_chain_backends` | The same federation on one Hardhat node and on a real 4-validator QBFT network, with the contract verifying the aggregate. Gas differs because newer EVM hard forks reprice modexp. | slide 23 |
| `F19_gas_breakdown` | Measured gas by contract method for 5 rounds with 8 hospitals, on-chain verification of the aggregate and ZK proof hashes. Round opening and the on-chain homomorphic check dominate. | slide 23 (alt.) |
| `F20_second_dataset_covertype` | Second dataset (Forest Covertype, 4 wilderness-area silos, MLP with 1,665 parameters). Client-level DP is expensive at this size and distributed DP shows no advantage over local DP with only 4 clients (a negative result); poisoning is only partly recovered. | backup slide |
| `F21_zk_proof` | The zero-knowledge proof that a committed update has bounded L2 norm: per-coordinate commitments and a Sigma proof of squares, a slack commitment, and a bit-decomposition range proof. | new slide |
| `F22_defence_coverage` | Defence coverage: which mechanism is the primary defence (filled) or a contributing one (open) for each attack. Each row is backed by a test and an experiment. | slide 20 (alt.) |
| `F23_qbft_network` | Real multi-node blockchain: 4 Besu validators on QBFT consensus tolerate 1 fault and halt safely with 2 down. | new slide |
| `F24_distributed_protocol` | One federated round as messages between separate OS processes: hospitals, the untrusted server and the contract. | new slide |
